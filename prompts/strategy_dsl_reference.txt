Strategy DSL v1 (normative finite grammar)
The strategy gene is one JSON object: {"version":"eagle-strategy-dsl-v1","rules":[...]}. No other fields. Maximum 16000 characters, 32 rules, condition depth 6, boolean fanout 8. No prose/code fields. Empty rules means idle.
Rule: {"actor":"Worker|Base|Barracks|Light|Heavy|Ranged","when":condition,"action":action}. Each actor is one friendly unit type. Process idle friendly actors in ascending unit ID, rules in array order. Select the first matching rule whose action can legally issue; if condition is false, target absent, path unreachable or guard fails, continue to the next rule. Issue at most one action per actor per cycle; unmatched actors idle. Reserve resources and destination cells across actors in the same PlayerAction before later actors are processed.
Condition: true, false, {"all":[conditions]}, {"any":[conditions]}, {"not":condition}, or {"compare":{"metric":metric,"op":"<|<=|==|!=|>=|>","value":number,...}}. Numbers finite within +/-1000000.
Metrics: stockpile (friendly current resources), time (current tick), actor_hp, actor_resources (carried resources), actor_id_rank (zero-based ascending ID rank among ALL current friendly units of the actor's type, including busy units), count and distance. count/distance require "entities":{"owner":"friendly|enemy|neutral","types":[unit types]}. Friendly/enemy types Worker,Base,Barracks,Light,Heavy,Ranged; neutral type only Resource. Optional nonnegative radius only on count restricts to Manhattan distance from actor <= radius. count counts current matching entities; distance is minimum Manhattan distance to matching entities, or positive infinity if none. No history, enemy action targets, future outcomes or invented state.
Entity target: {"kind":"entity","owner":"friendly|enemy|neutral","types":[types],"selector":"nearest|farthest|lowest_hp|highest_hp|lowest_id|hashed"}. Filter current entities by ownership/types and intrinsic action guard/reachability; select by metric with ascending unit ID ties. nearest/farthest use Manhattan distance. Cell target: {"kind":"cell","selector":"first_free_adjacent|hashed_free_adjacent"}; filter in-bounds adjacent cells for current occupancy and accumulated reservations; order y then x. Hashed selection sorts candidates by ascending ID (entities) or y then x (cells), selects index floorMod((time*31 + player*17 + actorID*13), candidateCount), using Java long integer arithmetic without persistent RNG.
Actions: {"type":"idle"}; {"type":"harvest|return|attack|engage|move","target":target}; {"type":"build|train","unit":unitType,"target":cellTarget}. No other fields. Worker supports all except train; combat units Light/Heavy/Ranged only idle,move,attack,engage; Base/Barracks only idle/train. Base trains Worker; Barracks trains Light/Heavy/Ranged; Worker builds Base/Barracks.
Intrinsic guards (must be implemented by generated Java): every actor is friendly and currently idle. harvest selects neutral Resource only, Worker carries zero, move by legal path toward selected Resource until adjacent then harvest. return selects friendly Base only, Worker carries >0, move toward Base until adjacent then return. Neutral Resource cannot be a combat or move target. attack selects enemy only and requires current attack range; engage selects enemy only, attacks in current range or moves one legal path step toward target. move selects friendly/enemy entity or free adjacent cell and issues one legal move step; entity-target move uses the existing deterministic pathfinder to an adjacent position (range 1), and an already-adjacent actor, self-target or unreachable target cannot issue that action and falls through; stationary producers cannot move. train/build require current available stockpile >= target unit cost (Worker1,Light2,Heavy2 in VERSION_ORIGINAL, Heavy3 in finetuned/non-deterministic tables; always use configured UnitType.cost,Ranged2,Base10,Barracks5), free adjacent placement and reservation, and the legal producer relationship above. Insufficient resource, occupied placement, absent target, or no legal path skips that rule. Path selection uses existing MicroRTS pathfinder with deterministic ordering. idle explicitly stops rule evaluation for that actor.
Java remains the generated phenotype implementing this declarative policy; there is no runtime DSL interpreter. Preserve ordered rule semantics, guards, selection ties and fallback exactly.

An action may alternatively be {"type":"choose","options":[1..8 actions]}. Nested choose is forbidden. Filter options to those able to issue a legal action under intrinsic guards, preserving option order, then choose index floorMod((time*31 + player*17 + actorID*13), legalOptionCount). idle is legal. If no option is legal, continue to next rule. This selects deterministic pseudo-random legal actions without RNG state.
