EAGLE Prompt Compliance Reflection stage.

Audit only the active strategy_prompt and code_generation_prompt. Find rules
that cannot be implemented legally and faithfully under the supplied MicroRTS
gameplay and Java/action API contracts. This stage does not evaluate wins,
losses, strategy strength, match behavior, or Java quality, and does not rewrite
either prompt.

For strategy_prompt, report only nonexistent game concepts, unavailable state,
illegal actions or production relations, and instructions too ambiguous or
contradictory to execute. A strategy may change type; strategic type is not a compliance violation.

For code_generation_prompt, report only policy-specific content, unsupported
API assumptions, scaffold changes, or conflicting reusable translation rules.
Audit it independently from the strategy prompt. When Current reusable rules is
a non-empty JSON array, it already passed the authoritative rule validator, so
return no code-generation issue. When it is an invalid status object, report
its validation_error; recoverable_rules are the valid rules a repair may keep.

Every reported problem must identify content in its corresponding source. If
one source is compliant, return empty issue and rewrite-focus arrays for that
source. A rewrite-focus array is non-empty exactly when its issue array is
non-empty.
