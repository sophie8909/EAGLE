Groq GPT-OSS Framework Design stage.

Design one complete Java MicroRTS CandidateAgent framework whose evolutionary
variation is restricted to a rich, explicit set of finite typed slots. The framework
is immutable within each version. Crossover and mutation replace only declared
slot markers. A separately configured periodic reflection stage may redesign
the complete framework while preserving typed slots and the MicroRTS contract.

Return the response required by the supplied JSON schema. Observe these
additional semantic requirements:

- schema_version is exactly eagle-framework-bundle-v1.
- framework_id is a lowercase slug containing only letters, digits,
  underscores, or hyphens, and starts with a letter.
- java_template is one complete compilable-shape ai.generated.CandidateAgent
  source file. It must import and use the vendored MicroRTS API and declare
  exactly `public final class CandidateAgent extends AbstractionLayerAI`.
  It must include both public constructors with these exact parameter types:
  `CandidateAgent(UnitTypeTable utt)` and
  `CandidateAgent(UnitTypeTable utt, AStarPathFinding pathFinding)`.
  It must also declare `public PlayerAction getAction(int player, GameState gs)`,
  `public void reset()`, and `public AI clone()`; do not use a no-argument
  constructor, a three-argument getAction, UnitAction as the return type, or
  the alternate `rts.AI.AbstractionLayerAI` API.
- java_template contains exactly one ordered
  `// EAGLE_AGENT_STRATEGY_START` / `// EAGLE_AGENT_STRATEGY_END` pair.
- Every declared slot appears exactly once inside that strategy region as the
  exact token `{{EAGLE_SLOT:<slot_id>}}`. Do not emit undeclared slot markers.
- The `marker` JSON field must contain the exact literal token with both closing
  braces, for example `"{{EAGLE_SLOT:priority_harvest}}"`; never omit either
  closing brace, add whitespace, or use a different spelling. The marker in
  `java_template` and the corresponding slot `marker` field must be identical.
- Slot IDs and choice IDs match `[a-z][a-z0-9_]{0,63}`. Use lowercase
  snake_case for every ID, for example `mix_balanced`, never camelCase such as
  `mixBalanced`.
- Slot kind is `integer`, `number`, or `expression_choice`.
- Integer and number slots have inclusive minimum/maximum bounds, a positive
  step, a default aligned to that step, and an empty choices array.
- Expression-choice slots have null minimum/maximum/step. Their default is one
  declared choice_id. Every choice is one side-effect-free Java expression,
  not a statement, method, block, declaration, patch, or complete source file.
- Provide enough independently combinable rules and parameters for meaningful
  evolutionary search: target at least 24 nonconstant slots, including at least
  6 expression-choice slots with at least 4 behaviorally distinct choices each.
  Cover economy/harvesting, expansion/building, unit production/composition,
  target selection, combat/movement/retreat, and state-dependent conditions and
  rule priorities. Use numeric controls for thresholds, ratios, and priorities,
  and expression choices to select genuinely different decision rules, not just
  alternate names or a menu of complete fixed strategies.
- Every exposed control must influence a reachable decision. Choices must be
  type-compatible at their marker, valid in their Java scope, and composable
  with the other controls. Keep legality checks and a deterministic fallback
  outside the configurable choices; explain interactions in the report.
- Do not expose file,
  network, reflection, process, class-loading, environment, or runtime-LLM APIs.
- slot_generation_prompt is a complete reusable prompt that asks another model
  for only the fixed JSON selection envelope supplied by the experiment,
  containing every slot_id mapped to a legal value/choice_id in control_genome.
  It must restate bounds, choices, and their behavioral meaning, and forbid
  Java/framework rewrites. The experiment supplies the exact-byte bundle hash;
  never invent a hash or add explanatory fields to the selection envelope.
- report is structural rather than prose wrapped around the bundle. It records
  architecture summary, ordered decision flow, invariants, assumptions, and
  risks. `slot_rationale` is an object whose keys are exactly all declared
  slot_id values and whose values are non-empty rationale strings.

Before returning, independently check every slot object: its `marker` is
exactly `{{EAGLE_SLOT:<slot_id>}}` with two closing braces, every `choice_id`
is lowercase snake_case, and the same exact marker occurs once in the Java
template. Return the complete corrected JSON object, not a partial repair.

Do not place Markdown fences around Java or JSON. Do not add keys outside the
provided response schema.
